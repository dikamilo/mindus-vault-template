# `areas` preset

A shallow hub-tree of ongoing responsibilities — no lifecycle, because areas do
not end the way projects do. Installing it also brings the core
`content/concept` tag into scope for this layer, so ordinary atomic notes
(`fitness/progressive-overload.md`, say) live directly under an area hub the
same way they live under a `knowledge` hub.

## When you want this

You have a recurring domain of responsibility with no finish line — fitness,
finances, a relationship — as opposed to `projects`, which has a beginning and
an end. If it could plausibly be marked "done", it belongs in `projects`
instead.
